# PhantomKnob 部署与分发安全性说明

本文档记录了应用发布与分发阶段的安全性考量，尤其是针对试用期授权（Trial Period）的保护机制。

---

## 1. 钥匙串访问权限与弹窗问题（开发阶段 vs 正式发布）

### 现象
在本地开发及调试阶段，每次修改代码重新编译并运行应用时，系统会弹出钥匙串访问请求，提示需要获取读取或修改 `trialStartDate` 等敏感钥匙串项的权限。

### 原因
* **Keychain 安全校验机制**：macOS 钥匙串（Keychain）根据应用的**代码签名**和 **CDHash（代码目录哈希）** 来判定访问者身份。
* **开发版自签名**：在本地开发编译时，应用通常采用 Ad-Hoc 临时自签名，每次代码变更编译出来的二进制哈希值都不相同。钥匙串服务会将每次编译后的二进制文件视作不同的应用程序，出于安全策略，每次均会弹窗要求用户确认凭证。
* **正式版不会频繁弹窗**：在生产/分发版本中，应用使用的是受信任的统一 **Apple Developer 证书** 签名，其中绑定了唯一的 `Team ID`。因为更新后的应用依然基于相同的 `Team ID` 进行签名，macOS 钥匙串服务会自动放行对属于该 `Team ID` 下 Keychain 条目的访问，用户在进行自动更新（OTA）或重新安装时将不会受到弹窗骚扰。

### 开发调试屏蔽方案 (已实现)
为了彻底消除本地频繁修改代码编译导致的钥匙串弹窗问题，代码在 `LicenseManager` 的构造函数中使用了编译条件宏：
* **`DEBUG` 模式下**：自动使用 `UserDefaults` 来存取 `trialStartDate` 等状态。因为 `UserDefaults` 不需要钥匙串的高级别权限，所以在开发调试时将不再会弹出任何权限询问窗口。
* **非 `DEBUG` 模式下（如生产 Release 构建）**：将自动切回高安全性的 `Keychain` 存储，确保防卸载重置等安全限制依然生效。

## 2. 试用期防重置与防破解策略（待以后实现）

在单机模式（不依赖网络服务器）下，试用期授权数据极易被用户重置。为了提高软件的防破解等级，建议未来实施以下优化方案：

### 2.1 隐蔽钥匙串键名（混淆 Key）
* **现状**：当前使用的 Key 名字为显眼的 `trialStartDate`、`licenseKey`、`licenseEmail`。破解者只需在系统的“钥匙串访问 (Keychain Access)”应用中搜索并删除对应条目即可重置试用期。
* **改造建议**：
  * 使用无意义的哈希值或伪装成系统内部库的标识作为 Key（例如：`com.apple.control.knob.state` 或 `com.phantomknob.device.token`）。
  * 将这些 Key 名字保存在代码里进行混淆，防止通过静态字符分析被轻易搜索到。

### 2.2 存储内容混淆与加密
* **改造建议**：
  * 写入钥匙串的数据不要存储明文的 ISO8601 格式时间戳。
  * 在写入前，对时间戳数据执行简单的加密/混淆（如使用本地硬编码的 Key 进行简单的 AES 加密或异或 XOR 操作），将其转换为乱码，使得哪怕破解者在钥匙串中看到了该条目，也无法确信其真实用途。

### 2.3 双重交叉验证（Keychain + 隐藏物理文件）
* **原理**：防止用户单独清理钥匙串或单独清理文件。
* **改造建议**：
  * 当试用开始时，在系统的 **Keychain** 和磁盘深处的 **隐藏文件夹**（如 `~/Library/Application Support/` 下某个伪装的小数据文件中）各自记录一份加密的试用开始时间。
  * **验证逻辑**：
    * 启动时同时读取 Keychain 与隐藏文件。
    * 如果 Keychain 中的数据被删，但隐藏文件数据存在，则以隐藏文件为准（并自动补写 Keychain）。
    * 如果隐藏文件被删，但 Keychain 数据存在，则以 Keychain 为准（并自动补写隐藏文件）。
    * 只有当两处的数据均被同时清理时，试用期才会被重置，这大幅提高了破解门槛。

### 2.4 二进制文件加固（防止逆向跳转）
* **说明**：单机授权校验的终极痛点是客户端代码可能被逆向破解者通过修改汇编指令（如将条件判断强制改为无条件跳转）来绕过。
* **改造建议**：
  * 在编译发布版时开启 Swift 编译器优化，并对核心授权检测方法进行混淆。
  * 将试用期状态的校验逻辑分散埋入核心功能的执行链路中，而不是只保留在统一的 `currentState` 方法里，增加逆向者修补二进制代码的难度。
