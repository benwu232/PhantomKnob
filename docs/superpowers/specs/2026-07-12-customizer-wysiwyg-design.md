# 旋钮定制面板 WYSIWYG 设计

## 背景与目标

当前的旋钮定制面板（`CustomizerHUDView`）是一个纯参数表单，存在以下问题：

1. **缺少视觉预览**：用户修改颜色、半径、旋钮类型等参数后，无法看到旋钮最终的外观效果，必须关闭面板实际操作才能验证。
2. **参数组织混乱**：所有参数（颜色、半径、输出翻译、方向、度数单位、元素定位信息）平铺堆叠，缺乏逻辑分组。双环模式下，内圈/外圈各自作为独立大卡片，导致颜色与行为参数交叉混杂。
3. **可理解性差**：双环旋钮和无级变速旋钮的概念对用户来说抽象，纯文字参数无法帮助用户理解这些模式的工作原理。

**目标：** 将定制面板改造为所见即所得（WYSIWYG）界面，让用户在调整参数时能实时看到旋钮外观变化，并通过交互式预览直观理解各模式的工作方式。

## 总体布局：上预览 + 下参数

面板采用纵向布局——顶部为可交互的旋钮预览区，下方为按逻辑重组的参数表单。

```
┌──────────────────────────────────┐
│  [App图标] 控件名称        ×关闭  │  ← 元数据卡片（精简）
├──────────────────────────────────┤
│                                  │
│        ┌───────────────┐         │
│        │   ◎ 旋钮预览   │         │  ← 可交互的旋钮预览区
│        │  (触控板旋转)  │         │     实时响应下方参数变化
│        └───────────────┘         │
│    "在此区域用触控板旋转试试"       │  ← 提示文字（首次/未交互时）
├──────────────────────────────────┤
│  [单旋钮] [双环] [无级变速]       │  ← ① 类型选择器
├──────────────────────────────────┤
│  🎨 外观                         │  ← ② 外观参数
│  颜色 / 半径 等                   │
├──────────────────────────────────┤
│  ⚡ 行为                         │  ← ③ 行为参数
│  输出翻译 / 方向 / 度数单位       │
├──────────────────────────────────┤
│  ▶ 高级信息（默认折叠）           │  ← ④ 元素定位标识
│  Bundle ID / AXRole / 层级链     │
└──────────────────────────────────┘
```

| 属性 | 当前值 | 新值 |
|------|--------|------|
| 宽度 | 400px | 440px |
| 高度 | 520px | 680px |
| 窗口级别 | `.statusBar` | 不变 |

## 预览区设计

### 预览区基本规格

- 位于元数据卡片下方，固定高度约 **180px**
- 居中显示旋钮，背景为微透明深色（与面板底色一致）
- 底部有一行提示文字：`"在此区域用触控板旋转试试"`，仅在用户未交互时显示，交互后自动隐藏

### 各模式预览内容

| 旋钮类型 | 预览显示 |
|---------|---------|
| **单旋钮** | 单色圆环 + 刻度盘 + 中心标记点。实时反映主题色和最小响应半径（内部留白区表示死区） |
| **双环旋钮** | 两个同心圆环，内圈和外圈各自有独立颜色。环间有视觉分界线，反映边界半径和迟滞间距。当前激活的环高亮，非激活环降低透明度 |
| **无级变速** | 径向渐变色环，**从外到内颜色渐深**（外圈=慢速=浅色，内圈=快速=深色）。用户指定外圈色和内圈色，系统用 HSB 插值自动过渡。中心显示实时倍率值（如 `1.5x`） |

### 交互行为

- 用户在预览区内用**触控板做旋转手势**，预览旋钮真实旋转
- **双环模式**：根据手指距离中心的远近，高亮当前激活的环（内/外），帮助用户直观理解「手指靠近中心 = 内圈精调，远离中心 = 外圈粗调」
- **无级变速模式**：中心倍率值随手指距离实时变化，渐变色环上出现位置指示
- 切换旋钮类型时，预览区有 **crossfade 动画**过渡

### 参数 → 预览联动

修改任何参数（颜色、半径、类型），预览立即更新，无需手动刷新。数据流：

```
@State 参数变化
    → save() 保存规则（已有逻辑不变）
    → 同时驱动预览区 OverlayView 重绘（SwiftUI 响应式绑定）
```

## 预览区交互实现

### 手势识别方案

不复用全局手势链（`MultitouchManager` → `GestureClassifier` → `KnobAlgorithm`），而是用**轻量级本地手势识别**。

原因：
- 全局手势链依赖 AX target、rule lookup 等重依赖，预览不需要
- 预览只需两个信息：旋转角度 和 手指到中心距离

做法：
- 在预览区叠加一个透明 `NSView`，监听 `touchesBegan/Moved/Ended`
- 复用 `KnobAlgorithm` 中的角度计算逻辑（`atan2` 差值算法），但不发送任何实际按键/滚轮事件
- 将计算出的角度和半径传给预览区的 `OverlayView`，驱动旋转动画和区域高亮

### 渲染方案

| 旋钮类型 | 渲染方式 |
|---------|---------|
| **单旋钮** | 复用现有 `OverlayView`，传入当前参数（themeColor, angle, rotationStyle="ticks"） |
| **双环** | 嵌套两个同心 `OverlayView`（内/外圈），各自有独立颜色和直径。当前激活环高亮，非激活环降低透明度 |
| **无级变速** | 扩展 `OverlayView`，用 `RadialGradient` 替换纯色填充。渐变使用 HSB 颜色空间插值，从外圈色过渡到内圈色 |

## 参数面板重组

### 分组结构

参数按「类型 → 外观 → 行为 → 高级」的逻辑排序，每个区块有清晰的分组标题：

#### ① 旋钮类型
- `SegmentedPicker`：单旋钮 / 双环 / 无级变速
- 位置不变，是参数区的入口

#### ② 🎨 外观

| 模式 | 外观区块内容 |
|------|------------|
| **单旋钮** | 主题色选择（色板 + 自定义色按钮）+ 最小响应半径滑块 |
| **双环** | 外圈主题色 + 内圈主题色 + 边界半径滑块 + 迟滞间距滑块 + 内圈最小响应半径滑块 |
| **无级变速** | 外圈色选择 + 内圈色选择（双色渐变）+ 最小半径滑块 + 最大半径滑块 |

#### ③ ⚡ 行为

| 模式 | 行为区块内容 |
|------|------------|
| **单旋钮** | 输出翻译 + 顺时针方向 + 度数单位 |
| **双环** | 分两个小卡片——**外圈**：输出翻译 + 方向 + 度数单位；**内圈**：输出翻译 + 方向 + 度数单位 |
| **无级变速** | 输出翻译 + 顺时针方向 + 内圈倍率（最小半径处） + 外圈倍率（最大半径处） |

**关键改变：** 双环模式不再把外圈/内圈作为独立的大卡片（颜色+半径+行为混在一起），而是按外观/行为分组，在行为区块内部用两个小卡片区分内/外圈。

#### ④ ▶ 高级信息（默认折叠）

- Bundle ID、AXRole、AXIdentifier 元数据行
- 层级链特征勾选（冲突检测与分叉点标记）
- 默认折叠，点击展开

## 无级变速旋钮的倍率插值与双色渐变

### 倍率与半径的关系

- **无硬性大小限制**：在物理计算中，倍率与半径是完全通过线性插值映射的。技术上不限制两个数值的相对大小。
- **直观命名**：为了避免“Min Scale”和“Max Scale”在数值大小反转时产生概念歧义，UI 界面上将输入框重命名为：
  - **内圈倍率（最小半径处）** (对应底层 `maxScale`)
  - **外圈倍率（最大半径处）** (对应底层 `minScale`)
- **自由指定**：用户完全可以设定内圈倍率小于外圈倍率（即靠近中心时响应更慢，远离中心时响应更快），系统会根据此配置做反向线性插值。

### 用户界面

在无级变速模式的「外观」区块中，提供两个独立的颜色选择器：

- **外圈色**（慢速端）：色板 + 自定义色按钮
- **内圈色**（快速端）：色板 + 自定义色按钮

### 渐变算法

使用 **HSB 颜色空间线性插值**：

1. 将外圈色和内圈色分别转换为 HSB 分量（Hue, Saturation, Brightness）
2. 对于给定的插值参数 `t`（0.0 = 外圈/最大半径，1.0 = 内圈/最小半径），分别对 H、S、B 线性插值
3. 色相（H）插值时取最短路径（处理色相环的 0°/360° 跨越）

### 应用场景

- **预览区**：使用 SwiftUI `RadialGradient(colors: [outerColor, innerColor], ...)` 渲染径向渐变
- **实际 Overlay**：根据手指到中心的距离，用 HSB 插值计算当前环色，传递给 `OverlayView`
- **数据模型**：`LinearKnobConfig` 新增 `outerThemeColor: String?` 和 `innerThemeColor: String?` 两个字段
