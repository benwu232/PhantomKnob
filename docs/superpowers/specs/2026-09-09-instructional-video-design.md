# PhantomKnob 教学视频设计规格

日期：2026-09-09
状态：待用户审查

## 1. 背景与目标

PhantomKnob 目前的教学素材只有文字安装说明和静态截图。核心交互（触控板双指旋转手势 → 悬浮旋钮 → 屏幕滑块跟随）是纯视觉体验，文字和截图无法传达。

本设计规划一套教学视频，同时服务三个月标（按优先级）：

1. **提高落地页转化**——访客 30 秒内看懂"这是什么、值不值得下载"
2. **降低上手门槛**——已下载用户卡在安装、辅助功能权限、手势上
3. **产品传播**——B 站 / YouTube / 社媒获客

**全局约束**：

- 双语一套素材：无配音、无字幕（或仅极简英文标注，见 §5），纯画面叙事
- 手势必须被看见：屏幕录制为主画面，右下角画中画显示手部触控板特写
- 零成本工具链：QuickTime + KeyCastr + 手机俯拍 + DaVinci Resolve

## 2. 总体策略：一次拍摄，金字塔剪辑

一个拍摄时段覆盖全部素材，从同一批母带剪出四份产出：

```
        ┌─ 产出 1：30s Hero 演示循环（从最佳场景素材裁出）
母带 ────┼─ 产出 3：场景合集短片（每场景独立成条）
        ├─ 产出 4：平台长视频（完整串联 + 转场）
        └─ 产出 2：安装引导（单独补拍系统对话框部分）
```

理由：布景、灯光、画中画版式一次统一，四份素材风格一致；多拍场景边际成本趋近于零。

## 3. 全局规格与拍摄设置

### 3.1 画中画版式（所有素材统一）

```
┌───────────────────────────── 16:9 主画面（屏幕录制）
│
│                    ┌────────┐
│                    │ 手部特写 │  ← 右下角，圆角矩形
│                    │ 俯拍触控板│     约 28% 宽度，细边框，轻投影
└────────────────────┴────────┘
```

- 主画面：QuickTime 屏幕录制，Retina 全屏（3360×2100），留足二次构图余量
- 画中画：手机俯拍触控板区域，只框住"双指 + 触控板边缘"，裁成 4:3
- 画中画**全程常驻**，包括没有手势的镜头——建立"看到手 = 真实操作"的信任感

### 3.2 同步方案（一次对齐，全场不用再管）

1. QuickTime 屏幕录制**开启 Mac 麦克风输入**，手机拍摄也带麦克风
2. 每个场景开拍前，对着触控板**拍一下手**：两台设备音轨出现同一脉冲
3. 剪辑时用 Resolve 的按音频自动同步；兜底方案："手指接触触控板瞬间 = 悬浮窗出现"手动对齐
4. 纪律：手机先开录 → 再开屏幕录制 → 拍手 → 开始动作；**场景中间不停机**，拍错整个场景重来

### 3.3 拍摄环境设置

| 项 | 设定 | 原因 |
|---|---|---|
| 系统语言 | **英文界面** | 双语素材最优解：UI 文字语言中性偏英文，中文用户对英文 macOS UI 接受度远高于反向 |
| 桌面 | 干净壁纸，Dock 只留会用到的 App，菜单栏隐藏杂项 | 视觉聚焦 |
| 光标 | 系统光标调大一号 + 后期高亮描圈 | 无声视频的"旁白" |
| 按键可视化 | **KeyCastr 全程开启** | 无声视频中"热键触发"必须被看见：按热键时屏幕浮现按键名 |
| 音量/亮度 HUD | 用系统原生 HUD | 观众零成本读懂的天然"字幕" |
| 手机俯拍 | 三脚架固定，**锁定曝光和白平衡** | 否则多次拍摄色调不一致，剪辑穿帮 |

## 4. 四份产出详细脚本

### 4.1 产出 1：Hero 演示循环

- **用途**：落地页首屏 `<video autoplay muted loop playsinline>`；GitHub README 转 GIF
- **时长**：30 秒（README 精简版 10 秒，见 §7）
- **来源**：不单独拍摄，从场景素材中选手势最流畅的段落裁出
- **硬性要求**：循环无痕——首尾画面状态完全一致（平静桌面 + 光标悬停）

**分镜表**（三场景结构，每场景完整"悬停→热键→旋转"）：

| 时间 | 主画面 | 画中画 | 说明 |
|---|---|---|---|
| 0-2s | 桌面平静态，光标缓移至菜单栏音量图标 | 手指悬空未接触触控板 | 开场 = 结束态（循环接缝） |
| 2-4s | 按热键，KeyCastr 浮现按键名，悬浮旋钮在光标下浮现 | 手指下移准备 | 讲清"怎么触发" |
| 4-11s | 双指顺时针旋转，旋钮转动，音量滑块上升 + 系统 HUD | 双指在触控板上画弧，幅度大 | 核心卖点 7 秒，1x 实速 |
| 11-12s | 光标停住，旋钮淡出 | 手指抬起 | 场景呼吸点 |
| 12-13s | **硬切**：浏览器全屏播放视频画面 | 同上 | 场景切换 |
| 13-20s | 光标移到进度条上 → 按热键 → 旋钮浮现 → 旋转 scrub 视频 | 双指画弧 | 场景 2 |
| 20-21s | 旋钮淡出 | 手指抬起 | |
| 21-22s | **硬切**：Photopea 画布界面 | 同上 | 场景切换 |
| 22-29s | 光标移到笔刷大小滑块 → 热键 → 旋钮 → 旋转调笔刷 | 双指画弧 | 场景 3 |
| 29-30s | 旋钮淡出，光标回到桌面平静态 | 手指离开触控板 | 与 0s 画面状态一致，循环闭合 |

**节奏规则**：旋转动作全部 1x 实速（卖点就是"顺滑"，加速即自毁）；只有呼吸点的停顿可以剪短。

### 4.2 产出 2：安装 + 权限引导

- **用途**：README 安装区、落地页"安装"章节（点击播放，非自动循环）
- **时长**：75 秒左右
- **核心任务**：解决最大流失点——辅助功能权限授予
- **允许 3-4 个极简英文标注**（本条视频特例，已确认）：`Download` / `Drag to Applications` / `Enable Accessibility` / `Done`

**分镜表**：

| 时间 | 画面 | 焦点处理 | 标注 |
|---|---|---|---|
| 0-2s | 桌面 → 打开浏览器 | 缩放：推近浏览器窗口 | |
| 2-8s | 打开 GitHub Releases 页，光标点 DMG 下载，下载进度条 | 缩放跟随光标 | `Download` |
| 8-16s | Finder 打开 DMG 窗口，拖 PhantomKnob.app 到 Applications（经典安装动效） | 缩放推近拖拽动作 | `Drag to Applications` |
| 16-20s | 打开 Applications 中的 PhantomKnob，首次启动 | | |
| 20-24s | 系统弹出辅助功能提示对话框，光标点"打开系统设置" | 缩放推近弹窗 | `Enable Accessibility` |
| 24-40s | 系统设置 → 隐私与安全性 → 辅助功能列表 → 光标点开 PhantomKnob 开关 | 缩放推近开关，开关变绿的瞬间稍作停留 | |
| 40-46s | 回桌面，菜单栏 PhantomKnob 图标出现，光标点一下图标展开菜单 | 缩放推近菜单栏图标 | |
| 46-70s | 光标移到音量图标 → 按热键（KeyCastr 浮现）→ 旋钮浮现 → 双指旋转调音量 + HUD | **成功时刻**，1x 实速，可轻微多转两圈展示顺滑 | `Done` |
| 70-75s | 定格：产品 logo + 官网 URL 卡片 | 淡入 | |

**缩放实现**：无 Screen Studio，用 Resolve 手动关键帧（全屏 → 放大 160% 对准目标 → 停 → 缩回），约 10 组关键帧。

### 4.3 产出 3：场景合集短片

- **用途**：落地页"场景"区、README、社媒；每条独立循环，可拼合集
- **时长**：每条 8-15 秒
- **拍摄清单**（全部浏览器可达，拍摄日无需安装额外软件）：

| # | 场景 | 展示的画面反馈 |
|---|---|---|
| 1 | 系统音量（菜单栏） | 系统 HUD + 菜单栏滑块 |
| 2 | 系统亮度（控制中心） | 屏幕 brightness HUD |
| 3 | YouTube 视频进度 | 进度条 scrub |
| 4 | Figma 网页版不透明度滑块 | 图层透明度实时变化 |
| 5 | Photopea 笔刷大小滑块 | 画布上笔刷圈实时变化 |

**每条的统一模板**（与 Hero 分镜单场景结构相同）：

```
悬停目标滑块 (1s) → 热键浮现 (1s) → 双指旋转 (4-6s, 1x 实速)
→ 效果反馈清晰可见 (2-3s) → 旋钮淡出 (1s) → 回到平静态 (1s)
```

每条拍 2-3 遍（手势手感每遍差异大，选最佳）；Hero 循环直接从这批素材中选段。

### 4.4 产出 4：平台长视频（B 站 / YouTube）

- **用途**：平台发布获客
- **时长**：90-120 秒
- **发布时配 BGM**（不违反"素材一套"原则；YouTube 可开自动字幕）

**结构表**：

| 时间段 | 内容 | 素材来源 |
|---|---|---|
| 0-8s | Hook：最佳手势片段 + 产品名文字卡 | 场景素材最佳段 |
| 8-25s | "这是什么"：悬浮窗出现 → 旋转 → 滑块跟随；实体旋钮对比叙事（3D logo / B-roll 空镜） | 场景素材 + 空镜 |
| 25-60s | 安装全流程 | 直接嵌入产出 2 主体 |
| 60-105s | 五场景轮播（每场景 8-9s） | 产出 3 素材 |
| 105-115s | CTA：logo + 官网 URL 定格 | |

## 5. 无声叙事五规则

1. **光圈即旁白**——光标调大 + 后期高亮描圈，视线永远知道该看哪
2. **缩放即镜头**——每步操作推近成为画面中心（Resolve 手动关键帧）
3. **画中画常驻即证据**——手始终在画里，无声反驳"这是剪出来的"
4. **实速即诚信**——旋转动作必须 1x 实速；只有呼吸点停顿可剪
5. **系统 HUD 即字幕**——音量/亮度原生横条，零成本读懂

语言策略：系统界面切英文；除安装视频的 4 个极简英文标注外，无任何字幕文案。

## 6. 后期流程与输出规格

流程：Resolve 按拍手音轨同步 → PiP 版式合成母带（2160p）→ 裁四份产出 → 输出。

| 产出 | 分辨率 | 格式与去向 |
|---|---|---|
| Hero 循环 | 2160p | 落地页 MP4（自动循环）+ README GIF |
| 安装引导 | 2160p | MP4，落地页点击播放 |
| 场景短片 | 1080p | MP4 循环 + GIF |
| 长视频 | 2160p | MP4（B 站 / YouTube 上传） |

合成版式（Resolve 轨道 2 画中画：缩放 28% → 右下角定位 → 圆角遮罩 + 细边框 + 轻投影）。版式定稿后若需经常补拍，再固化为 ffmpeg `composite.sh`（overlay + geq 圆角），第一套不依赖它。

## 7. 分发嵌入与技术陷阱

- **落地页首屏**：替换现有 hero demo 区域（纯图像），改为 `<video autoplay muted loop playsinline poster="assets/screenshot_hud.png">`
- **GitHub README 不支持自动播放视频** → 用 GIF：15fps + 800px 宽 + gifski 压缩，目标 ≤8MB；仍超标则单独剪 10s 精简循环专供 README
- **视频不进 git 仓库**：MP4 放 GitHub Releases assets；repo 是 GitHub Pages 站点，大视频会拖慢 clone/部署。GIF 若 ≤8MB 可直接进 repo
- **README 现有截图位置**：安装教程区可放产出 2 的 GIF 版或链接 Releases 视频

## 10. 非目标（YAGNI）

- 不做出镜口播、不配中文/英文配音
- 不做多语言字幕版本
- 不制作动画手绘示意（用实拍画中画替代）
- 不在第一套素材前购买 Screen Studio / ffmpeg 脚本化
